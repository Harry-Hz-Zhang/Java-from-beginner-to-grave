# 第 1 章 Java 语言基础

## 要点

### Java重要特点：
1. Java语言是面向对象（oop）。
2. Java语言是健壮的。Java的强类型机制、异常处理、垃圾的自动收集等是Java程序健壮性的重要保证 
3. Java语言是跨平台性的。［即：一个编译好.class 文件可以在多个系统下运行，这种特性 称为跨平台］
4. Java语言是解释型。

### 第一个 Java 程序

最简单的写法是不写包声明，源文件长这样：
```java
public class HelloJava {
    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}
```

在源文件所在的目录里执行 `javac HelloJava.java`，会生成 `HelloJava.class`，接着执行 `java HelloJava` 就能看到输出结果。

#### 编写源文件要遵守的八条规则

第一，Java 源文件以 `.java` 作为扩展名，源文件的基本组成部分是类（`class`），例如本例中的 `Hello`。

第二，Java 应用程序的执行入口是 `main()` 方法，它有固定的书写格式：
```java
public static void main(String[] args) { ... }
```

第三，Java 语言严格区分大小写。

第四，Java 方法由一条条语句构成，每个语句以分号「;」结束。

第五，大括号都是成对出现的，缺一不可。
习惯上先写出成对的大括号，再往里面填写代码。

第六，一个源文件中最多只能有一个 `public` 类，其他类的个数不限。

第七，如果源文件包含一个 `public` 类，那么文件名必须按这个类的名字命名。

第八，也可以把 `main` 方法写在非 `public` 类中，然后指定运行这个非 `public` 类，此时入口方法就是该类的 `main` 方法。

#### 运行时要留意的五个坑

第一，`package` 语句会改变类的真名。
源文件里一旦写下 `package com.harry.fundamentals.ch01;`，这个类的完整名字就变成 `com.harry.fundamentals.ch01.HelloJava`，而不再是 `HelloJava`。
这种由包名和类名拼起来的完整名字叫作全限定名。

此时直接执行 `java HelloJava` 会失败，虚拟机抛出 `NoClassDefFoundError`，并在括号里写出它真正期望的那个名字。
正确做法是先切换到包目录的根目录，也就是 `src/main/java`，再用全限定名运行：

```bash
cd src/main/java
java com.harry.fundamentals.ch01.HelloJava
# Hello, Java

java com.harry.fundamentals.ch01.HelloJava.harry    
# I'am Harry
```

第二，编译通过不代表能够运行。
`javac` 只检查语法和类型，它不关心源文件所在的目录是否与包名一致；
`java` 命令则要求目录层级与包名严格对应。
两个命令的判断标准不同，所以经常出现编译成功、运行时才报错的情况。

第三，删掉 `package` 语句来回避问题并不可取。
删掉之后确实可以用 `java HelloJava` 跑通，但这个类会落进默认包。
默认包指的是没有包名的类所在的那个特殊位置，而 Java 规定有包名的类无法引用默认包里的类，因此以后写的代码都用不上它。
集成开发环境还会用红色波浪线提示「缺少 package 语句」，这个提示来自代码检查，并不是编译错误。

第四，类名不要和包的最后一段目录重名。
当源文件放在 `ch01/HelloJava/HelloJava.java` 这样的位置时，包名末尾和类名都叫 HelloJava，读报错信息很容易误以为名字重复写错了。
规范的做法是让包只到 `ch01` 这一层，把源文件直接放在 `ch01` 目录下。

第五，日常练手可以改用单文件源码模式。
Java 11 以后的版本支持直接执行源文件，执行 `java HelloJava.java` 就会完成编译和运行两步，既不用手动生成字节码文件，也不受包名影响。
这样也不用担心包名问题了

### Java代码规范

1. 类、方法的注释，要以javadoc的方式来写。
2. 非Java Doc的注释，往往是给代码的维护者看的，着重告述读者为什么这样写，如何修改，注意什么问题等
3. 使用tab操作，实现缩进,默认整体向右边移动，时候用shift+tab整体向左移
4. 运算符和 = 两边习惯性各加一个空格。比如：2 + 4 * 5 + 345 - 89
5. 源文件使用utf-8编码
6. 行宽度不要超过80字符
7. 代码编写次行风格和行尾风格


### autoConvert

```text
+--------+
|  char  | ----------------------------+
+--------+                             |
                                       v
+--------+     +---------+         +-------+     +--------+     +---------+     +----------+
|  byte  | --> |  short  | ------> |  int  | --> |  long  | --> |  float  | --> |  double  |
+--------+     +---------+         +-------+     +--------+     +---------+     +----------+

```

数据类型按照容量与精度大小排序的具体规则包含以下两条并列路径：

* **字符型转换路径：** 字符型（`char`）在参与运算时会首先转换为整型（`int`），随后依次提升为长整型（`long`）、单精度浮点型（`float`），最终能够提升为双精度浮点型（`double`）。
* **数值型转换路径：** 字节型（`byte`）首先转换为短整型（`short`），接着提升为整型（`int`），随之依次转换为长整型（`long`）与单精度浮点型（`float`），最终提升至双精度浮点型（`double`）。
