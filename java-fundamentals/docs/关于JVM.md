# JVM

## 初步了解 JVM 虚拟机栈 / 栈帧结构图


> 图例：VM Stack = 虚拟机栈，Frame = 栈帧，Local Variable Table = 局部变量表，Operand Stack = 操作数栈，main() Frame = main 方法栈帧，0~4 = 局部变量表的槽位号。

1. **栈帧**：Java 每调用一个方法，就会给这个方法分配一块专属的内存空间，这块空间叫栈帧。
2. **压栈**：方法一调用，就在 VM Stack 里给它分配栈帧，这个动作叫压栈。
3. **栈帧的组成**：每个栈帧包括局部变量表和操作数栈。
4. **局部变量表**：存这个方法执行过程中的局部变量。槽位从 0 号开始，依次加 1。main 方法的 0 号槽位放的是 `args`。
5. **操作数栈**：存程序执行过程中的数据。

### **`int i = 10;` 的字节码执行过程**

```text
(1) after: bipush 10                    (2) after: istore_1
    10 is pushed onto the stack             pop 10, store it in slot 1

    +----------+   |        |               +----------+   |        |
 4  |          |   |        |            4  |          |   |        |
    +----------+   |        |               +----------+   |        |
 3  |          |   |        |            3  |          |   |        |
    +----------+   |        |               +----------+   |        |
 2  |          |   |        |            2  |          |   |        |
    +----------+   |        |               +----------+   |        |
 1  |          |   |        |            1  | 10 (i)   |   |        |
    +----------+   |        |               +----------+   |        |
 0  | args     |   |  10    |            0  | args     |   |        |
    +----------+   +--------+               +----------+   +--------+
 Local Variables  Operand Stack          Local Variables  Operand Stack
```

> 图例：① 执行 `bipush 10` 之后，10 被压入操作数栈；② 执行 `istore_1` 之后，栈顶的 10 被弹出，存入局部变量表 1 号槽位（即变量 i）。Local Variables = 局部变量表，Operand Stack = 操作数栈。

字节码的执行顺序是这样的：
```text
0: bipush 10    // 把常量 10 压入操作数栈
2: istore_1     // 弹出操作数栈的栈顶元素，存到局部变量表 1 号槽位（变量 i）
3: return       // 方法返回，main 的栈帧出栈
```


## 方法执行时候的内存变化

首先：JVM 只是一套规范，各个厂家对这套规范有不同的实现，非常具有代表性的例如 Oracle 的 HotSpot

```text

+===================================================================+  +-------------------------------+
|                                                                   |  |                               |

|                                                                   |  |                               |

|  | push  vvv    ^^^  pop       |   |                            | |  |    classes are loaded first.  |
```

> 图例：Heap = 堆，Method Area = 方法区，m() frame / main() frame = m 方法 / main 方法的栈帧，push = 压栈，pop = 弹栈，new Obj = new 出来的对象，Metaspace = 元空间，PermGen = 永久代。

【方法区】
  * 方法区存放的是字节码（类信息）。
  * 程序开始执行时，先进行类加载。假设类加载器加载 Hello.class，那么这个 Hello.class 就存储在方法区当中。
  * Java 8 之后，方法区的具体实现叫做元空间（Meta Space）。
  * Java 7 及之前，方法区的具体实现叫做永久代（PermGen）。

【堆】
  * new 出来的对象都放在堆里，堆被所有线程共享，由 GC 负责回收。

【栈帧的压栈 / 弹栈】
  * 方法调用时才会分配内存空间（栈帧），此时发生“压栈”动作。
      例：main 调用 m，m 方法栈帧压在 main 方法栈帧的上面。
  * 方法结束时，给这个方法分配的空间就会释放，此时发生“弹栈”动作。
      例：m 执行完先弹出，然后回到 main 继续执行（后进先出）。
  * 每个栈帧都包含：局部变量表 + 操作数栈。

【总结】
  1. JVM 是一套规范。
  2. VM Stack、Heap、Method Area 都是规范中的名词。
  3. Java 8 之后，方法区的具体实现叫做元空间（Meta Space）。
     元空间使用的是操作系统的本地内存，以前的永久代在堆当中。
  4. 为什么元空间改用本地内存？为了避免 OOM（内存溢出）：
     永久代大小固定，类加载多了容易报
     java.lang.OutOfMemoryError: PermGen space；
     本地内存空间更大，可以按需增长。
